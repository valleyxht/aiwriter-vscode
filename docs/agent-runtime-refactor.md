# AI SDK Agent 执行循环重构

本分支从 `befd230` 开始，替换主 Agent 和专业 Agent 的 LangGraph 执行循环。模型通信继续通过本地 Vercel AI SDK，所有请求直连用户配置的 API 地址。

## 执行方式

使用 AI SDK 的逐轮生成与流式接口，应用控制模型调用、工具批处理及下一轮输入。没有引入固定意图分类器或任务专用路线。

未采用 `ToolLoopAgent` 自动执行全部工具：当前工具批处理需要保留只读最多三个并发、写入顺序、审批、重复查询限制，以及 OpenAI 兼容接口返回文本工具调用时的解析。这些策略集中在工具执行模块，模型协议交给 SDK。不会因为本次重构增加额外的模型调用。

- `src/ai/runtime/agent.ts`：请求局部的执行循环、完成与退出控制。
- `agent-state.ts`：状态与累计数据的类型和更新规则。
- `agent-model.ts`：单轮模型输入预算、流式交付、空响应恢复。
- `agent-tools.ts`：工具校验、批处理、写入记录和证据进展。
- `agent-limits.ts`：额度判断和停止结果。
- `agent-messages.ts`：消息正文与工具协议的兼容边界。

已移除 StateGraph、Annotation、图路由、图递归限制及 LangGraph 依赖。剩余 LangChain 依赖也已移除：应用消息由本地数据结构表示，历史摘要直接调用 AI SDK，Markdown 整理工具使用项目既有校验契约，Embedding 使用 AI SDK 的 OpenAI 兼容适配。保留原有 JSON 提示词、摘要分批与失败回退，以及会话存储格式。LangSmith 通过官方 AI SDK 包装器独立接入，保持请求级父追踪和模型调用子追踪，不再使用框架回调或图节点追踪。

## 验证范围

原有测试保留业务断言，仅更新执行入口和注入名称。覆盖模型兼容、推理协议保留、实时正文、工具额度、只读并发与写入顺序、检索停止、专业 Agent、审批与事务等。

新增执行循环测试覆盖：流式状态快照、Token 累计、提前结束后不执行待处理工具、预先取消、并发请求状态隔离、终止错误不重复调用。

运行 `npm run compile`、`npm run lint` 和 `npm run test:unit`。本机模拟服务测试需要允许回环连接。

## 手工对比

在原工作区和本 worktree 使用相同模型、配置、材料及任务，分别验证：直接讨论、精确资料查询、跨章节资料检索、审批后写入、拒绝写入、执行中取消以及服务错误。比较日志中的模型调用次数、总 Token、总耗时和首段正文显示时间，同时核对答案覆盖与文件修改。

自动化验证使用模拟模型，不证明真实供应商表现或确定的性能提升。当前预期收益主要是移除图调度与状态归并抽象，让执行路径更直接、便于维护；实际性能差异需要上述同条件测试。
