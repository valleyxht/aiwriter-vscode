# 会话历史摘要

长对话在模型调用前按可用历史预算触发滚动摘要。实现复用当前 LangChain 0.3 的 `ConversationSummaryBufferMemory.predictNewSummary()`，不依赖升级到新版 Agent 中间件。

## 输入与预算

上下文顺序为：系统提示 → AIWRITER.md → 静态参考资料 → 较早历史的累计摘要 → 近期原始对话 → 当前请求及附件/选中文本 → 本次工具证据 → 最终 Token Budget 检查。

Engine 从上下文窗口扣除输出预留、安全余量、系统提示、项目记忆、当前请求和附件，并为工具描述及新证据预留空间，得到历史预算。历史超过该预算的 80% 时，尝试压缩到约 60%；始终保留最近至少两个用户轮次的原文。摘要上限为历史预算的 20%，最多 2048 tokens。空间不足或没有可压缩的旧轮次时，由已有最终预算检查兜底。

旧消息按完整用户轮次选择，超长摘要输入则连续分批处理，每批包含已有摘要，并按摘要模型的输入预算计数。摘要提示保存在 `src/ai/runtime/prompts/history-summary.json`，要求区分用户已确认设计、助手建议、被否定的方案和未决事项，以最新纠正为准。

## 为什么适配 Memory

本地安装的 `ConversationSummaryBufferMemory.prune()` 对临时消息数组调用 `shift()`，没有将裁剪后的数组写回聊天存储；它还按消息而非完整用户轮次切分。因此复用组件的滚动摘要生成方法，由项目管理切分范围、预算和持久化。

## 会话与回退

`Session.history` 保留完整原始聊天记录。`Session.historySummary` 单独记录摘要内容、覆盖消息数和覆盖前缀的 SHA-256。下一次请求只发送摘要及未覆盖的历史，不重复发送已压缩消息。较早摘要放在历史位置，属于对话背景，与 AIWRITER.md 分开。

摘要在生成并校验成功后保存到对应会话；切换会话、重启插件时恢复。撤回到摘要覆盖范围内会清除摘要；历史前缀发生改变也会使摘要失效。撤回后迟到的摘要不会覆盖当前状态。

摘要调用复用模型配置、厂商适配、取消、重试、并发控制及请求用量观测，操作名为 `history_summary`。空输出、超出摘要预算、输出被服务商截断或调用失败时，不保存部分摘要；保留已有摘要和原始历史，由最终预算裁剪兜底。摘要失败会显示进度提示，并在请求观测中记录 `history_summary_failed`。

摘要是有损的会话背景，不替代原文。它只覆盖历史对话；本轮附件及工具证据不纳入跨轮摘要。历史中的单次超长输入会按连续片段摘要，保存的覆盖边界仍以完整用户轮次为准。
